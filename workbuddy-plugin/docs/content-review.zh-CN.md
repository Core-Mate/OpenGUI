# 发内容前需要审核（内容审核模式）

开启后，OpenGUI 在对外发布文字内容前会先暂停，把要发布的内容交给你审核。批准后，运行时还会逐字核对，才允许真正发布。

## 开启方式

- 创建任务时，确认页「执行设备」下方的「高级选项」里，勾选「发内容前需要审核」后再点「开始执行」。旁边的「?」悬停时会显示简要说明。
- 默认不开启。开启状态只能由你在确认页选择，模型不能开启或关闭，也不会要求你关闭。
- 任务开始后不能更改。恢复同一任务时沿用原来的设置。
- 「评论」场景（逐条审核评论再发送）本来就要求审核，与这个选项无关，行为不变。

## 哪些内容需要审核

| 需要审核 | 不需要审核 |
|---|---|
| 发帖或笔记、评论、回复、私信等，带文字的对外发布 | 点赞、关注、收藏等不含文字的操作 |
| | 搜索、填写表单、浏览页面等普通输入和导航 |

## 审核流程

1. **起草**：模型写好要发布的完整文字后，先提交审核，不会直接发布。提交的内容包括：
   - 内容类型（帖子、评论、回复、私信）；
   - 发布账号、发布位置（帖子链接、个人主页、收件人等）、上下文；
   - 标题（如果有）和正文。
2. **暂停等待**：任务暂停。工作台左侧出现审核卡片，对话里提示等待你审核。
3. **你的决定**：
   - **批准并发送**：使用当前版本。
   - **修改草稿**：在卡片里直接改。保存后以你的版本为准，模型只能使用这一版。
   - **跳过此篇**：可以填写原因。跳过的内容不会发布，任务继续处理其他部分。
4. **输入并核对**：模型按批准的原文输入，然后读回输入框里的实际文字。只有和批准原文逐字一致，才允许点击「发布」或「发送」。如果平台改动了文字（例如自动转换表情），卡片上会显示差异，由你决定。
5. **发布并核验**：每次批准只能用于一次发布。发布后，模型截图确认内容已经出现，才记为「已发布」。结果不确定时记为「结果未知」，不会自动重发。

## 运行时如何强制执行

审核不依赖模型自觉。WorkBuddy 的模型和后台配置的模型执行动作时，都要经过同一个检查入口：

- **动作必须标明是否发布**：开启后，每次点击、滑动和回车键都必须标明是否会对外发布（无 / 发布 / 发送等）。没有标明的动作直接拒绝，不会发到手机。
- **发布前必须已批准**：标为「发布」或「发送」的动作，没有对应的已批准审核时被拒绝，不会发到手机。
- **读回文字必须一致**：带审核的发布，要求输入框读回的文字与批准原文完全一致，否则拒绝。
- **同一内容不重复发**：同一账号在同一位置发过的相同文字，不能再次提交发布。评论和回复仍是同一账号对同一目标只发一条。

## 进度与报告

- 工作台左侧显示「已发布并核验」的条数，以及每条的状态：待你审核、已批准、已发布、已跳过、结果未知。
- 任务报告的概要表会标明「发内容前审核：已开启」。「内容审核」一节逐条列出：
  - 内容类型、账号、位置、标题和最终正文；
  - 各个版本，以及你的每次决定和时间；
  - 输入核对记录和发布证据。

## 已知局限

- 拦截依赖模型如实标明「发布 / 发送」类动作。开启后，未标明的动作一律拒绝，降低了漏标的可能；但如果模型把发布按钮误标成「无」，这一次发布无法被拦下。发布后的截图核验和报告记录可以帮助发现这类情况。
- 带图片、话题、可见范围设置的帖子，目前只审核文字和标题，图片等素材不在审核范围内。
- 不支持批量审核：一次只处理一条，上一条处理完（发布、跳过或确认结果）后才能提交下一条。

## 相关接口（供开发参考）

- 确认页开始执行：`POST <工作台>/board`，参数 `{ action: "start", modelId, deviceId, contentReview: true }`。
- 会话状态返回 `contentReview: true`。
- 审核工具 `opengui_review_comment` 新增 `kind`（post / comment / reply / message）和 `title`；读回和核验沿用 `opengui_comment_input`、`opengui_verify_comment`。
- 相关错误码：
  - `content_action_unclassified`：动作未标明是否发布；
  - `review_required`：发布前没有已批准的审核；
  - `content_already_published`：相同文字已在该位置发布过。
