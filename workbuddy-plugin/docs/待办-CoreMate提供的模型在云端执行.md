# 待办：CoreMate 提供的模型在云端执行

- 状态：待办（未开始），当前继续使用本地执行
- 记录日期：2026-10-05
- 涉及范围：CoreMate 后端（另一个代码仓库）与本插件 `workbuddy-plugin/`

## 1. 现状

插件有两种执行方式，两种都在本机运行「看截图 → 决定下一步 → 执行动作」的执行循环：

| 执行模型 | 执行循环在哪里 | 模型推理 |
|---|---|---|
| 跟随 WorkBuddy | WorkBuddy 自己的模型通过 MCP 工具逐步操作 | WorkBuddy 的模型 |
| CoreMate 提供的模型 | 插件本地的执行器（`src/configured-runner.ts`） | 每一步经 CoreMate 后端的模型代理 `/api/agent-config/runtime/proxy/<配置ID>/v1/...` 转发给模型供应商，供应商密钥留在后端 |

选择 CoreMate 提供的模型时：
- 截图和任务内容每一步都随推理请求发往后端，再转发给模型供应商。
- 规划、重试、结束判断等逻辑都在插件里，提示词和执行策略需要随插件发版更新。

CoreMate 桌面端在正式环境下也是同样的结构：执行循环在用户电脑上，模型调用走后端代理。

## 2. 目标

选择 CoreMate 提供的模型时，由云端运行执行循环，插件只负责：

- 执行云端下发的设备动作（点击、滑动、输入、按键、启动应用），并回传结果；
- 截图并上传；
- 在工作台展示进度和执行记录，支持人工接管、暂停、取消和评论审核；
- 生成任务报告。

预期收益：

- 执行策略和提示词集中在服务端迭代，不必随插件发版；
- 模型用量和计费在服务端统一管理；
- CoreMate 桌面端与 WorkBuddy 插件共用同一套执行能力；
- 插件不再需要适配各家模型的协议和坐标约定。

需要关注的代价：

- 截图要上传到云端存储，隐私说明需要相应更新；
- 多了网络往返，需要处理断线、恢复和重复执行；
- 云端下发动作必须有严格的安全边界（见第 4 节第 5 条）。

## 3. 调研结论（2026-10-05，基于 CoreMate 桌面端代码）

- **云端执行能力已存在，但只在测试环境启用。**
  - CoreMate 有独立的「手机执行 Worker」：在服务器上运行执行循环，用户电脑只执行动作、上传截图。
  - 后端的启用条件写死为测试环境；正式后端调用相关接口会返回 503「云端手机 Agent 尚未启用」。
  - 正式环境也没有部署 Worker。
- **正式环境的 CoreMate 桌面端同样在本机执行**，与本插件现状一致。
- **现有接口与桌面端绑定，第三方客户端无法直接使用：**
  - 创建手机任务只接受桌面端来源（`WARROOM`），并要求桌面会话 ID。
  - 云端执行依赖「模型配置版本」体系（`model-configuration`），与插件读取的 `agent-config` 模型目录不是同一套。根据 2026-10-03 的部署核查，正式数据库尚未建立对应的数据表。
  - 客户端需要同时维持两条 Socket.IO 长连接：一条是执行通道，一条是设备 RPC 通道。
  - 设备指令走 JSON-RPC，包含 `observe`、`tap`、`swipe`、`inputText`、`pressButton`、`startApp`、`openDeepLink`、`executeShell`、`close`。指令带幂等键和尝试序号（fence）。
  - 截图要通过签名地址上传到私有对象存储；进度事件需要客户端回传后端；执行通道需要定时心跳续租。

## 4. 后端需要完成（CoreMate 后端）

1. 把云端执行的启用条件改为配置项，在正式环境部署手机执行 Worker。
2. 在正式数据库执行模型配置相关迁移，并在管理后台发布带手机角色的模型配置；明确插件选择的模型如何对应到云端的模型配置版本。
3. 准备截图用的私有对象存储，以及执行租约和 Worker 分配用的 Redis。
4. 支持 WorkBuddy 插件作为任务来源（例如新增 `WORKBUDDY` 来源，不要求桌面会话）。最好提供面向第三方客户端的简化接入方式，例如：一个创建并启动任务的接口、一条设备通道、一个进度事件流。
5. 给第三方客户端的设备指令设白名单：只下发点击、滑动、输入、按键、启动应用、截图等动作，不下发 `executeShell` 这类指令。
6. 明确云端执行的计费或额度规则，以及额度不足时的提示方式。

## 5. 插件需要完成（`workbuddy-plugin/`）

1. 选择 CoreMate 提供的模型时，改为创建云端任务并建立设备通道；云端不可用时，保留现有本地执行作为后备。
2. 设备驱动：把云端指令映射到现有的 ADB / scrcpy 执行（坐标换算、文本输入、按键、启动应用），拒绝白名单之外的指令；变更类动作按幂等键去重，不自动重放。
3. 截图上传：按签名地址协议上传，画面未变化时不重复上传。
4. 进度展示：把云端事件映射到工作台的执行步骤、本次运行记录、鼠标动画和任务报告。
5. 控制：人工接管、恢复控制、暂停、取消和评论审核与云端控制指令对接；处理断线重连与租约失效。
6. 更新 README 中的数据去向说明，以及 `connector/skills/control/SKILL.md` 的执行说明。

## 6. 验收标准

- 在正式环境选择 CoreMate 提供的模型后，执行循环在云端运行，插件日志中没有本地模型推理请求。
- 点击、滑动、中英文输入、按键、启动应用在 Android 真机和模拟器上都能正确执行，坐标准确。
- 接管、恢复、暂停、取消、断线重连后，不重复执行已经完成的变更类动作。
- 工作台步骤、本次运行记录、任务报告与云端执行结果一致。
- 云端服务不可用时，能回退到本地执行或给出明确提示，不卡死任务。
- 白名单之外的指令（如 shell）被插件拒绝，并留有记录。
