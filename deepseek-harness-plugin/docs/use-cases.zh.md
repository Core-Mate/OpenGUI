# OpenGUI 常用场景

[English](use-cases.md) | 中文

OpenGUI 通过当前 DSH 会话模型操作已授权的 Android 手机，并按任务需要调用插件托管的浏览器。先在 `OpenGUI` Tab 选择手机，再使用 `@OpenGUI` 或 `/opengui`。模板和任务完成后的建议都只会填入草稿，不会自动发送。

## QA 助手

```text
@OpenGUI 作为测试，帮我走查当前 APP，先产出测试用例，再按用例逐项执行并汇总问题。遇到登录、支付、删除数据等动作先征求确认。
```

适合冒烟测试、回归走查、页面一致性检查和缺陷复现。建议在任务里说明测试账号、重点模块和禁止执行的动作。OpenGUI 会按已选手机分别执行，适合比较不同系统版本或机型。

## 运营助手

```text
@OpenGUI 作为运营，帮我运营目标平台并完成基础互动；发布、私信、账号修改等外部动作前先征求确认。
```

适合查看评论、整理待回复对象、完成低风险互动和汇总运营结果。请明确平台、账号范围、语气和互动边界。任何发布、私信、账号资料变更或其他对外动作都应先确认。

## 手游助手

```text
@OpenGUI 帮我领取游戏 A、游戏 B 和游戏 C 的每日福利；遇到付费、抽卡或资源消耗时先征求确认。
```

适合签到、领取邮件、收取免费体力和重复性的每日福利。请写清游戏名称和允许领取的内容。付费、抽卡、兑换稀缺资源、加入或退出公会等不可逆动作应先确认。

## 多手机协同

在 `OpenGUI` Tab 勾选多台手机，再提交一个任务。检测成功后 OpenGUI 会锁定本次设备快照，并为每台手机创建独立控制子任务。适合：

- 对多个系统版本执行同一组回归用例；
- 批量领取多台设备上的免费日常奖励；
- 对比不同账号或设备上的页面状态。

等待手机连接期间仍可更改选择；进入模型路由后不可切换，避免任务中途操作错设备。

## 手机与浏览器协同

```text
@OpenGUI 检查手机 APP 中显示的活动规则，再打开官方网站核对截止时间，最后汇总差异。不要提交表单。
```

路由 Agent 会判断是否需要 `phone_agent`、`browser_agent` 或两者顺序协作。即使任务最终只操作浏览器，非空 OpenGUI 任务也会先检查手机连接。托管 Chromium 只在实际需要时，经用户确认后下载。

## 使用边界

- 空 `/opengui` 和裸 `@OpenGUI` 只显示用法，不检查手机或模型。
- 当前模型明确支持图片时直接使用；不兼容时才进入专用视觉模型回退。
- 能力错误不会自动重试，避免重复产生手机或浏览器副作用。
- OpenGUI Tab 的实时画面只读；需要单独放大查看时可手动打开“独立窗口”，任务完成不会自动关闭该窗口。
- 点击任务完成卡片中的追问只会生成 `@OpenGUI` 草稿，请检查后再发送。
